## 二、根因：不是"采样器绑错"，是"两套 UV 空间混用"

`albedo ≡ 0` 的完整因果链（每一步都能在源码里对上）：

```
我们的顶点适配层
  vTexCoord   = vec4(UV0, 0.0, 0.0)      ← 方块图集 UV（只能常量供值，GAP-007）
  vTexCoordAM = vec4(UV0, 0.0, 1.0)
        ↓
包的视差函数  GetParallaxCoord()
  coord = vTexCoord.st;                  ← 起步就是上面的图集 UV
  ReadNormal(coord)                       ← 却要按「材质贴图集」的 UV 去采样  ★错配★
  for (...) coord += stepDir;            ← 沿视差方向推进
        ↓
albedo = texture2DGradARB(texture, newCoord, dcdx, dcdy) * vec4(color.rgb, 1.0);
        ↓
采样落进图集的透明黑区域 ⇒ albedo 恰好 0 ⇒ 地形全黑
```

★ **关键错配**：我们喂的是**方块图集**的 UV，`ReadNormal()` 期望的是**材质贴图集**的 UV
—— 两套完全不同的坐标空间与尺寸。这不是某个绑定填错了，而是**能力缺失**（GAP-009）。

🔖 **一个值得记的细节**：这条推理我们自己的诊断文案**早就写对了**
（`PackVertexAdapterGenerator.java:137-142`）：

> 「若画面亮起来 ⇒ 压零项在**视差分支**（即 GAP-007 的 `vTexCoord`/`vTexCoordAM` 常量供值）」

只是当年真正去跑这个实验时，观测面被另一个缺陷（闪烁）污染，读数不可信 ⇒ 推理正确却没兑现。
**是"把观测面修干净"这件事本身解锁了后续所有进展。**

## 四、A 与 B 的差别（实测口径）

### 4.1 A 的两个落点，实测对比

| | 落点①：关 `PARALLAX` | 落点②：关 `ADVANCED_MATERIALS` |
|---|---|---|
| 主目标地形 luma | **`96.1485`** | **`96.1485`** |
| 主目标 meanRGB | `(90.96, 97.85, 94.61)` | `(90.96, 97.85, 94.61)` |
| 内部产物规模 | **`colorTargets=8` `samplers=7` `varyings=15`** | `colorTargets=1` `samplers=5` `varyings=9` |
| 用户失去的包特性 | 视差 | 视差 **+ 高级材质**（AO / 光滑度 / 自发光遮罩…） |
| GAP-003 多附件语义 | ✅ **保住** | 🔴 **落空**（塌成 1 槽） |

🔶 两个落点**在地形区逐像素同值**，整帧差异只来自云层 ⇒ **该按工程依据选，不按视觉选。**

### 4.2 A 与 B 的本质差别

| 维度 | **A · 按能力关掉** | **B · 补最小材质集语义** |
|---|---|---|
| 改哪一层 | **选项层**：按能力门控掉依赖缺失素材的特性 | **资源/绑定层**：提供类型正确、语义可解释的数据 |
| 用户看到 | 地形正常，**相关特性消失** | 特性保留，材质项表现为"无 AO、法线朝上"这类**可解释缺省** |
| 是否改写用户包配置 | 🔴 **会**（必须 WARN + 可开关 + 登记） | ❌ 不动 |
| 触碰 X27 | 🔴 正面触碰 | ✅ 不碰 |
| 工作量 | **小**（选项覆盖机制已验证，零代码即可生效） | **大**（要么接第三方材质集资产，要么做逐方块材质 UV ≈ GAP-009 主体） |
| 风险 | 视觉退化但**可预测** | 可能"看着对其实错"（本轮已踩过两次） |

### 4.3 🔖 B 其实已经做了一半

`bridge/NeutralMaterialMaps` 已经在给 `specular` / `normals` 绑**中性缺省**，
且 `h10` 实测过"两个采样器确实被读到、48.41% 像素变化"。

⇒ **B 真正缺的不是"给张图"，而是"UV 空间对"** —— 这也是为什么补了中性缺省之后
视差分支仍然把 albedo 压成 0。

## 五、建议与理由

**建议：A 落在 `PARALLAX` 层，并按"能力门控 + 显式登记 + 可开关"的形态实现；B 作为后续正解。**

理由：

1. **视觉等价**（§4.1 实测）⇒ 选 A 不损失用户可见质量。
2. **多保住 8 槽 gbuffer** —— 多附件正是本项目**兼容支柱的主线**（GAP-003），
   取落点②会把它直接打回原点。
3. **少砍一个包特性**（只关视差，不关高级材质）⇒ 在 X27 的张力下更站得住。
4. **成本近乎为零**：选项覆盖机制已实测可用（`命中 N/N` 有命中正证），**零代码**即可生效。
5. A 与 B **不互斥**：A 是止血（当下就能让地形正常），B 是正解（让效果真正正确）。
   只做 B 的话，中间这段时间用户看到的仍是黑地形。

⚠️ **但「按能力门控」的具体形态仍需你定**（我不自行决定）：

- 门控**哪些**特性？（视差一个？还是「一切需要逐方块材质 UV 的特性」？）
- 怎么**判定能力缺失**？（`ADVANCED_MATERIALS` 开 + 我们没有材质集 ⇒ 关 `PARALLAX`？）
- **能否被用户覆盖**？（用户手动开了视差要不要尊重？ Iris 的做法是给警告后照做）
- 缺省行为要不要**逐包可关**？
