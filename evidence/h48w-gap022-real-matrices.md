### 1.1 🔴 第一道坎：`flat()` 打的「rN」其实是数学上的**第 N 列**

按「rN = 第 N 行」去算 `clip.z/clip.w`，`d=1` 得 **20.0**；而同一行日志自己打的真实读数是
**0.04995361** ⇒ 两者矛盾 ⇒ 判读方式错了。改成「rN = 第 N 列」重建数学矩阵后，
**三个读数全部逐位复现**（差 < 1e−9），且 `Q·Q⁻¹ = I`（最大偏差 5.38e−8，float 噪声量级）。

🔖 这条不是吹毛求疵：上一轮「矩阵翻不动」的结论就是死在**行列序 + 自造矩阵**这两件事叠一起。
⇒ 教训：**凡是靠日志反推矩阵，必须用日志里另一条独立量（这里是 `windowDepth@…`）先校验读法**，
   校验不过就不许往下推。

重建出的数学矩阵（行优先）：

```
Q   行2(z) = [0, 0,  4.883051e-5,  0.05000244]
Q   行3(w) = [0, 0, -1.0,          0.0        ]
⇒ z_en(d) = 0.0500024399/d − 4.883046e-5      （对 v=(0,0,−d,1)）
```

## 二、由真实矩阵**反解**出引擎真正的视锥参数

要求「翻完深度」与「标准 GL 前向 Z」逐点相等（两者都是 `a + b/d` 形状，且在两端点相等 ⇒ 恒等），
解出：

```
near = 0.0499999984   ≈ 0.05
far  = 1024.001        ← 🔴 不是 512
```

🔴 **这就是上一轮否证的错处**：上一轮拿 `zNear=0.05 / zFar=512` 去比较，
于是「`D·P` 与标准 GL 矩阵逐元素差 1.0」——那不是矩阵翻不动，是**比较基准的 far 取错了**。
（登记表 GAP-022 里那句「joml 的 `m32` 是 ±0.05 而不是 ±1，所以只改 z 行得不到 GL 投影」
同样是这条错推断的产物：`0.05000244` 恰恰就是 `near`，它本来就该在那儿。）

## 三、推导与四项验证（全部用真实矩阵，不用自造矩阵）

记 `row_z` = Q 的第 2 行、`row_w` = Q 的第 3 行。取左乘矩阵

```
D2 = 单位阵，但第 2 行 = (0, 0, −2, 1)      ⇒  row_z' = row_w − 2·row_z
```

| # | 判据 | 实测 |
|---|---|---|
| A | `D2·Q` 与**标准 GL `[-1,1]` 投影**逐元素最大偏差 | **3.046e−09** ⇒ 就是它 |
| B | `D2⁻¹`（第 2 行 = `(0,0,−½,½)`）满足 `D2·D2⁻¹ = I` | **0.0** |
| C | 配对：`(D2·Q)⁻¹ == Q⁻¹·D2⁻¹` | **5.383e−08**（float 噪声）⇒ **不需要重新求逆** |
| D | 包自己那条路（`window → 2w−1 → P⁻¹`）往返视空间 z | 见下表，**逐位回到原值** |

```
d=    0.050 : 1−z_en=0.000000031  (ndc+1)/2=0.000000031  反解 z=  −0.050000
d=    1.000 : 1−z_en=0.950046391  (ndc+1)/2=0.950046391  反解 z=  −1.000000
d=   16.000 : 1−z_en=0.996923678  (ndc+1)/2=0.996923678  反解 z= −16.000001
d=  128.000 : 1−z_en=0.999658186  (ndc+1)/2=0.999658186  反解 z= −128.000007
d= 1024.001 : 1−z_en=1.000000000  (ndc+1)/2=1.000000000  反解 z= −1024.001046
```

### 3.1 🔴 关键区分：**[0,1] 窗口深度** ≠ **`[-1,1]` NDC 矩阵**，两个都要、但不能混

- 上一轮试的是 `D`（第 2 行 `(0,0,−1,1)` ⇒ `row_z ← row_w − row_z`）。它**确实**把窗口深度翻成
  `1 − z_en`（偏差 1.1e−16，x/y NDC 完全不变），也**确实**等于标准 GL **`zZeroToOne`（[0,1]）** 投影
  （逐元素 5.0e−11）。⇒ 「翻不动」从头到尾都是假的。
- 但它**不是包要的那一份**：包里 `GetLinearDepth` 一系先做 `depth*2−1` 再乘
  `gbufferProjectionInverse` ⇒ 它要的是 **`[-1,1]` NDC 口径**的矩阵。
  喂 `[0,1]` 那份的后果被数值抓到：**反解出来的视空间距离恰好是真值的一半**
  （d=1 → −0.500244，d=16 → −8.063，d=128 → −68.27）。
- `D2` 才是对的：它的 `clip.z/clip.w` 是 `[-1,1]` NDC，而 GPU 存进 `depthtex` 的窗口深度
  恰好 `= (ndc+1)/2 = 1 − z_en` ⇒ **深度那一半（已实现的 `glWindowDepth = 1 − z`）与矩阵这一半互相自洽**，
  不是两件事。

## 四、结论（可写进实现的那一份）

```
gbufferProjection          = D2 · P_engine            （D2 第 2 行 = (0,0,−2,1)）
gbufferProjectionInverse   = P_engine⁻¹ · D2inv       （D2inv 第 2 行 = (0,0,−½,½)）
depthtex0 窗口深度          = 1 − z_engine            （= (D2·P 的 ndc.z + 1)/2，已证自洽）
gbufferPreviousProjection / gbufferPreviousProjectionInverse 同理，用**各自那一帧**的矩阵
```

⇒ **GAP-022 的「矩阵那一半」不再是未推状态。**
同时必须撤两条旧记录：① 「`ADVANCED_MATERIALS` 默认 true」那类档位归因错误已在 §二十二处理；
