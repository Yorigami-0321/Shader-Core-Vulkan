## 二、主项：名字不得压过声明类型（h38 登记的待改项）

### 2.1 旧代码的洞

```java
// 注释原文：「它们全都是 2D ⇒ 先按名字定，再对没命中的按维度兜底」
switch (name) {
    case "shadowtex", "shadowtex0", "shadowtex1" ->
        return new Binding(name, type, ViewKind.SHADOW_DEPTH_2D, "绑专用 1x1 D32 桩…");
    ...
}
```

🔴 这个 `switch` **无条件**先生效。于是若某个包写：

```glsl
uniform sampler3D shadowtex0;   // 名字命中，但维度是 3D
```

就会拿到**一张 1x1 D32 的 2D 深度图** —— **正是 GAP-012 修掉的那类「拿 2D 冒充 3D」**，
只是换了个入口、**而且从没被登记过**。

### 2.2 修法：名字只选**来源**，声明类型约束**维度**

```java
if (!declaredNon2D(name, declaredType)) {     // 非 2D 声明不走名字规则
    Binding byName = byName(name, type);
    if (byName != null) {
        return byName;
    }
}
// ↓ 落到既有的「类型路径」：sampler3D⇒VOLUME_3D / cube⇒UNSUPPORTED / …
```

- **行为不变**：2D 声明与**裸 `sampler`**（维度未知）仍走名字规则 —— 既有 7 条绑定逐条照旧。
- **行为改变**：非 2D 声明一律落到类型路径，由**类型**决定。

🔖 为什么裸 `sampler` 仍走名字规则：维度未知时不猜（X9），
但也不因此**剥夺**名字规则 —— 那会把既有行为一并改掉，而本条只修那个确凿的洞。

## 三、🔖 顺带：QD-04 棘轮当场把我拦下来了

改完第一次跑测试：

```
MethodLengthRatchetTest > 主源码 >60 行方法数不得超过基线（QD-04 棘轮） FAILED
```

`decide()` 从 36 行涨到 **63 行**（超过 `LIMIT=60`）。

🔖 **没有上调基线**，而是把名字规则抽成两个方法：

| 方法 | 职责 |
|---|---|
| `byName(name, type)` | 名字 → **来源**（命中返回绑定，未命中返回 `null`） |
| `declaredNon2D(name, type)` | 声明类型是否蕴含**非 2D** 维度 |
| `decide(name, type, warnings)` | 编排：先问类型、再问名字 ⇒ **36 行** |

> 这条红灯恰好证明了 `h35` 立的那条纪律有用：
> **「规范写下来了」不等于「有东西让它保持正确」** —— 这次是**代码**让一条规范保持了正确。

## 四、副项：GAP-011 —— 用**移动机位**试（此前从未试过）

### 4.1 🔖 此前所有闪烁测试的共同盲点

回头看 `h16`–`h38` 的全部闪烁取证：`.client` 取图时**机位一律不动**。
而原始症状是**用户在正常游玩时**观察到的（`h16` 由用户现场确认）。

⇒ **静态机位很可能根本触发不了那个 bug。** 本轮补上这个条件：
**12 个 yaw（90°→360°→60°）× 每处连拍 3 帧 = 36 帧**。

### 4.2 结果：确实有抖动，**但不是闪烁**

同机位 3 帧的黑色占比抖动：

```
yaw=150   30.951% → 28.787% → 28.783%   spread=2.169 pp   ← 最大
yaw=180   32.375% → 30.702% → 30.587%   spread=1.788 pp
yaw=120   26.870% → 26.061% → 26.064%   spread=0.809 pp
（其余 9 处 ≤ 0.587 pp）
```

### 4.3 🔖 把这 2.169 pp **证伪**成闪烁（关键的一步）

「抖动」本身什么都不能说明 —— **区块流送**同样会动这个数。
所以对抖动最大的 `yaw=150` 做**逐带**分解（f1 vs f2）：

| 屏幕带 | black f1 | black f2 | delta |
|---|---|---|---|
| sky | 45.350% | 45.378% | +0.027 pp |
| **mid（y=120..250）** | **70.019%** | **63.019%** | **−7.000 pp** |
| **terrain（y=250..430）** | 0.735% | **0.000%** | **−0.735 pp** |
| hud | 3.597% | 3.597% | +0.000 pp |

判读：

- 变化集中在 **mid 带**，且方向是**下降** ⇒ 是**有内容载入**（暗像素变亮），**不是内容消失**。
- 更关键：**terrain 带的黑像素降到 0.000%** ⇒ 那一刻地形**全部点亮**、
  **没有任何一块变黑**。
- 闪烁的定义是「在有画面与**全黑**之间高频切换」 ⇒ 那应该表现为
  **terrain 带黑像素占比**大幅**上升**。**这里恰恰相反。**

⇒ **判定：2.169 pp = 区块流送，不是 GAP-011。**

### 4.4 结论

- GAP-011 在 **Vulkan 后端 + 移动机位 + 36 帧**条件下**仍然复现不出来**。
- 🔖 代价要说清：本轮**不是**证明了「GAP-011 不存在」，只是把触发条件又扩大了一圈仍未触发。
  剩余未试过的条件：真实玩家移动（走路/飞行/下矿）、光照变化（昼夜/天气切换）、
  不同分辨率、多区块视距。**已如实登记。**
