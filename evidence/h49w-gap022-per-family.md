# h49w · GAP-022「按程序族分别供值」落地 ⇒ **周期 3 的整帧黑消失**

> 被测改动：`OfUniformManager.gather(..., Family)` + `glConventionFor(family, switchOn)`：
> `gbuffers_*` 一族**无视开关**留引擎口径，`composite*/deferred*/final` 才吃 `mrt.depthGlProxy`。
> 开关：`mrt.depthGlProxy`（本臂 = `true`；默认值本轮**没翻**，理由见 §四）。
> 对照基线：`evidence/h49t-chain-black-frames.md`（同一套逐级观测面，只差 `depthGlProxy` 一项）。

## 一、判据（同臂同观测面，唯一差异 = `mrt.depthGlProxy` false → true）

| 指标 | h49t（开关关，AO 开） | **h49w（开关开 + 按族供值，AO 开）** |
|---|---|---|
| `trace1deferred1:c0` 输出为 0 的帧 | **62 / 185** | **1 / 177**（且那 1 帧是 #1 预热帧） |
| bad 帧间隔 | 逐字 `[3,3,3,3,3,3,3,3,3]` | **凑不出间隔**（周期没了） |
| 帧尾 `main` 是否有内容 | 每 3 帧一次为 `0.0000` | **每帧都有**（`166.88 / 150.22 / 55.55 / 28.03 / 47.60 / 50.57 / 47.88 …`） |
| `[GAP-022/family]` 分族自报 | 不该有（开关关） | **1 条** ⇒ 证明「链翻了、`gbuffers_*` 没翻」这件事在日志里看得见 |

🔑 结论：**包默认档（AO 开着）下的周期性整帧黑，被 GAP-022 的按族供值修掉了。**
这追了十几轮的症状（用户 2026-10-06 的「黑一下正常一下，但物品栏和手一直正常」）
第一次有了**可复现的对照数据**把它归零。

## 二、为什么「按族」是这件事的关键（而不是「把开关打开」）

h48z 那轮已经证明：**同一个 uniform 不能整链一起翻** ——
`gbufferProjection` 同时是 `gbuffers_*` 的**顶点阶段**投影矩阵
（转译终稿逐字 `gl_Position = gbufferProjection * gbufferModelView * position;`），
而本设备深度值域是 `[0,1]`（`DeviceInfo.isZZeroToOne=true`）、**没有** GL 那步 `(ndc+1)/2` 视口映射
⇒ 给 `gbuffers_*` 喂 `D2·P` 会让 clip.z 落到 `[-1,1]`、光栅化深度越界。
所以此前 `depthGlProxy=true` 是「半翻比不翻更坏」的取证档，**不能默认开**。

本轮把它拆成两族：链（passthrough 顶点 + 包片元按 GL 口径写分支）翻，`gbuffers_*` 不翻。
⇒ 于是「开着」第一次变成一件**可以说清含义**的事，而 AO 需要的正是链那一份 GL 口径
（`ambientOcclusion.glsl:52 float ao = 0.0;` + `:55 if (z >= 1.0) return 1.0;`
+ `:60 GetLinearDepth(z, projectionInverse)` —— 反向 Z 下这三个凑一起就是「累加全落空 ⇒ 写黑」）。

## 三、决策的离线钉法

`UniformFamilyTest` 3 条：开关开着时只有 `CHAIN` 吃 GL 口径 / 开关关着时两族都是引擎口径
（= OFF 态逐字不变）/ 族集合恰好两个（加第三族必须显式想过它的顶点阶段用不用这个矩阵）。
另外两条既有守卫**跟着长**而不是被放宽：
`DepthConventionPairTest`「一帧只许读一次开关」在本轮中途真的变红过（我在自报里又读了一次配置），
修法是**读一次存局部、把值传进报告**，不是改断言。
`MethodLengthRatchetTest` 也变红过一次（`drawPostChain` 60→61 行），修法是**提取** `requireChainReady`。

## 四、为什么默认值**没翻**（诚实清单）

1. **画面侧的完整判据还没看**：GAP-022 的关闭条件写的是三件事 ——
   `isSky = z == 1.0` 认对天空、光柱/镜斑/体积云出现在**正确像素**、SSR 不再拿垃圾 `viewPos`。
   本轮只量到「黑帧归零 + 每帧有内容」，**没看图**。（下一臂就是看图。）
2. `main` 的亮度整体下移（`160.0 → 115.65`、`44.3 → 29.03`）——
   这是 AO **开始真的起作用**（乘数 < 1）的预期方向，但**没有对照图就不能判它对不对**。
3. 周期 3 的**来处**仍未判（为什么恰好 1/3 帧）：本轮只证明了「链拿到 GL 口径之后它不再发生」。
   三个候选（`MappableRingBuffer` 深度=3 的相位、`frameCounter` 一帧被 `gather()` 推进 2~4 次、
   金字塔/代次节奏）留在登记表上。
⇒ 所以 `mrt.depthGlProxy` **默认仍 false**，等 §四.1 的看图判据过完再翻。

## 五、本轮**不覆盖**什么

1. 没看图（§四.1）；没测 `isSky`/光柱/镜斑这些**像素位置**判据。
2. 周期 3 的机制未判（只证明了它被这条修法**压住**）。
3. 水/云的画面判据本轮仍没重跑 —— 它们此前都受这条黑帧干扰，
   **修好之后需要重测**（X37：改了共享状态，引用过它的旧结论要重跑）。
   具体要重测的：`c1@afterTerrain` 的水覆盖是否还是「断续」、云覆盖是否还是 ~1-2%。
