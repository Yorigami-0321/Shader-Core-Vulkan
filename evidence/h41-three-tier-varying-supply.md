## 二、独立复核：结论是「原来的说法对」

从 `minecraft-patched-26.3.0.41-beta.jar` 反汇编 `DefaultVertexFormat` 静态块：

```
BLOCK  = Position, Color, UV0, UV2            <- 4 条，无 Normal
ENTITY = Position, Color, UV0, UV1, UV2, Normal
```

=> 代码里那句注释「适配层可读取的原版地形顶点属性，`DefaultVertexFormat.BLOCK`，字节码核实」
**是准确的**。本轮**没有推翻任何东西**。

🔖 **把「复核没发现问题」也写进证据**: 只写「修好了什么」而不写「复核证实了什么没坏」，
会让下一轮以为原结论仍未验证。

## 三、诊断说了假话，危害不是措辞

### 3.1 旧诊断

对 7 条 varying **一律**输出：

> `varying 'X' 只能按常量供值（原版地形顶点缓冲无对应属性，登记为 GAP-007）`

### 3.2 事实

| varying | 实际来源 |
|---|---|
| `vTexCoord` | `= vec4(UV0, 0.0, 0.0)` -- **`.xy` 就是真实的 `UV0`** |
| `vTexCoordAM` | `= vec4(UV0, 0.0, 1.0)` -- 同上 |

BLOCK 格式**确实有** `UV0` 属性。缺的不是「数据源」，而是**图集重映射**
[依赖同样缺失的 `mat`] 与 `z/w` 分量。

### 3.3 🔖 为什么这会误导后来人

照旧诊断，读者会推断：「`vTexCoord` **完全没有数据源**」
=> 「要拿到它，**必须改网格顶点格式**」。

而实际上它**已经有真值部分**，即 `.xy`。
这会直接影响将来 GAP-007 修法的取舍:
「改网格格式」的成本远高于「补一个重映射」，
误判会把一个中等成本的动作当成高成本动作而搁置。

🔖 归纳成一句可复用的纪律:
> **诊断文本本身也是结论，必须和被诊断的事实一样经得起反例。**
> 本项目此前栽过的同类坑: h33 的死开关、h34 的日志刷屏 -- 都是「描述与现实脱钩」。

## 四、改成三档

| 档 | 成员 | 理由文本 |
|---|---|---|
| **真值** | `Position / Color / UV0 / UV2`; MULTIDRAW 时另有 `ChunkPosition / ChunkVisibility` | 无需理由 |
| **部分真值** | `vTexCoord` / `vTexCoordAM` | 「`.xy` 取自真实的 `UV0`，BLOCK 格式确有该属性，但缺图集重映射矩阵，依赖 mat，同样是 GAP-007，与 `z/w` 分量」 |
| **纯常量** | `mat, recolor, normal, binormal, tangent` | 「原版地形顶点缓冲无对应属性，登记为 GAP-007」，原文本**保持不变** |

实现上 `Result` 记录新增 `partialSupplies` 一档，摘要行改为分别报两档条数。

## 五、Vulkan 运行期，原文

```
varyings=15（纯常量供值 5 条：mat, recolor, normal, binormal, tangent；
           部分真值供值 2 条：vTexCoord, vTexCoordAM）
```

两条诊断同时在场且**文本互不串台**:

- 纯常量档: 「只能按常量供值（原版地形顶点缓冲无对应属性，登记为 GAP-007）…」

`backend=Vulkan` 成立、ERROR **0**、`残留游戏进程数=0`。

## 六、🔖 守卫：其中一条是反向断言

```java
// 部分真值档的诊断**不得**包含「无对应属性」
assertFalse(joined.contains("无对应属性"), ...);
assertTrue(joined.contains("UV0"), ...);
assertTrue(joined.contains("图集重映射"), ...);
```

🔖 为什么要**反向断言**而不是正向断言「必须包含某句」:
正向断言挡不住「把两档合并成一句话」这种退化 --
合并后既含新词也含旧词，正向断言照样通过。
**反向断言直接锁死那句话不许回来。**

另有断言: 纯常量档那五条**不得**被顺手挪进「部分真值」。
