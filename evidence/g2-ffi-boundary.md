# G2 · FFM 边界开销实测 —— 按批保留 27.7%，按条只剩 20.0%–23.9%

> **§5.1 闸门里唯一被跳过的一关**。闸门顺序是 G0 → G1 → **G2** → G3 → G4，
> G2 从未做过。G1 算出的 26.6%–27.7% **把 FFI 边界开销当成了 0** —— 本文件去填那个 0。
>
> 结论先行：**按批粒度下收益几乎全保留；按条粒度下会掉到 20.0%–23.9%，最坏情形正好压在
> §5.2 的 20% 阈值上。** 而 T18 明令禁止按条。

## ✅ panic 边界实测（N5 首次拿到运行时举证）

```
panic 边界实测：always_panics() 返回 -1（期望 -1）→ 已被 catch_unwind 兜住
```

Rust 侧**真的 panic 了**（stderr 有 `panicked at src/lib.rs:50`），能返回 `-1` 且 JVM 存活
⇒ **unwind 没有穿过 Java 帧**。

🔖 **这条比「Cargo.toml 里没写 panic = abort」更强**：若有人误加了 `panic = "abort"`，
这里不会返回 -1，而是**整个 JVM 进程直接终止** —— 也就是说这个探针**能在运行时抓出铁律被违反**，
而不只靠读配置。

## 结论：26.6%–27.7% 的收益，两种粒度下各剩多少

以 `sum_len/cached-handle`（最贴近真实载荷：缓存句柄 + 传指针）为准，
分母 G0 口径修正后基线 895.3ms，G1 节省 248.0ms：

| 粒度 | 边界开销 | 净收益 | **端到端** | 跨趟区间 |
|---|---:|---:|---:|---|
| **按批（550 次）** | **0.030 ms** | 247.97 ms | **27.7%** | 27.7% |
| **按条（623,804 次）** | **33.7 ms** | 214.3 ms | **23.9%** | **20.0% – 24.2%** |
| 按条 + 每次重取句柄 | 1243.6 ms | **−995.6 ms** | **−111.2%** | −141.1% – −86.1% |
| 按批 + 每次重取句柄 | 1.096 ms | 246.9 ms | 27.6% | 27.6% |

### 三条可直接用于决策的判断

1. **按批粒度下，FFI 边界开销可以忽略**：0.030ms / 248ms = **0.012%**。
   「26.6%–27.7% 的收益在真实接线后还剩多少」⇒ **基本全保留（27.7%）**。
2. **按条粒度下会掉到 20.0%–23.9%**，最坏情形**正好压在 §5.2 的 20% 阈值上**。
   而 §7.3 的噪声红线是 ±9% ⇒ **这个区间的宽度已经和噪声同量级，不可依赖**。
   换句话说：**T18「按批不按批」的禁令不只是架构洁癖，它直接决定 G 线成不成立。**
3. 🔴 **「每次重新取句柄」在按条粒度下是灾难性的（−111.2%）** ——
   边界开销（1243.6ms）**比全部收益（248ms）大 5 倍**。
   按批粒度下它无害（1.096ms）。⇒ **句柄缓存与批粒度必须同时做，只做其中一个都不够。**

## 🔴 本文件**没有**证明的事

| 未覆盖 | 说明 |

## 🔖 本轮踩到的两个坑（都很阴险，记录下来）

**① `invokeExact` 是签名多态的，返回类型写错会「安静地」测错东西。**
把包装接口写成返回 `Object`，javac 就把调用点推断成 `()Object`，而句柄是 `()long`
⇒ 每次调用抛 `WrongMethodTypeException`。**异常被 catch 吞掉后不会崩**，
只会把「异常开销」记成「跨界开销」—— 实测一度给出 `noop/cached = 641.8ns`
这种明显不对的数。是**纯 Java 基线对照**把它暴露出来的（修好后降到 40.7ns）。

**② 忘了纯 Java 基线，就会把循环开销算成跨界开销。**
`invoke()` + `sink +=` 的循环本身约 20ns/次。`noop/cached` 实测 40.7ns、
扣掉基线后净 20.6ns —— 若不扣，会把开销**高估近一倍**，进而高估按条粒度的总代价。

## 下一步建议

1. **接口按批设计**（T18 已经这么要求）—— 本文件给了它第一次的量化依据：0.012%。
2. **句柄必须缓存** —— 按条粒度下这是 5 倍于收益的灾难。
3. 补一个**传大载荷**（整份源码文本）的场景，验证批量传输本身的开销。
4. G1 还差**转译相**与 **`pack/` 解析相** ⇒ 按 §5.1，G3/G4 仍不得开始。
