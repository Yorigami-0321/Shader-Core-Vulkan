# h16 · 🔴🔴 症状是**高频闪烁**，不是「一直黑」—— 用户观察推翻了单帧截图的判读

> 任务来源：`AGENT_CONTEXT.md` §10.21 ⑨ 第 1 条（测 `color`）。
> 取证方式：实现 color 探针 + 三道闸 + MCP 截图，**并由用户现场观察修正了判读**。
>
> 判定：🔴 **本轮最重要的一条是症状本身**：8 槽地形 pass 每帧都在**污染主目标**，
> 表现为**高频闪烁**（有画面 ⇄ 全黑）。这是一个支柱②（稳定）级别的缺陷，

## 〇、一句话结论

我抓到的截图是 99.89% 纯黑，本以为「画面一直是黑的」。
**用户现场观察：屏幕在高频地从「有画面」变黑、又变回有画面。**
🔖 也就是说 —— 纯黑**只是闪烁的一个相位**，而「有画面」的那些帧，恰恰是**原版渲染**。
⇒ **我方 pass 每帧在主目标上留下一层黑**，两相交替 ⇒ 闪烁。

## 三、🔴 真正的缺陷：8 槽 pass 每帧污染主目标（支柱②）

`FullscreenPassHook.onAfterLevel` → `MrtTerrainPass.drawTerrain` 是**每帧**执行的
（日志 `ORDER-MARK` 只打 1 次，但那只是**一次性**埋点，不是频率）。

🔖 症状与该机制完全吻合：`drawTerrain` 每帧打开 render pass 并把附件清成诊断色；
当附件与主目标共享视图时（`terrainToMain`），主目标就被**每帧清黑 + 画上黑色地形**，
原版地形在下一帧才回来 ⇒ **高频闪烁**。

⚠️ 本轮**未定位到具体是哪一行**造成主目标被写（`terrainToMain=false` 时槽 0 指向哪个视图）。
⇒ 登记为 **GAP-011**，是当前**最高优先级**项：它让画面不可用，比全黑本身更严重。
