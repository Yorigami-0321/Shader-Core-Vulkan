# 迭代维护协议（三层防乱）

> **定位**：通用方法论，零项目特定信息，永远不过时。
> **存放位置**：项目根目录 `AGENTS.md`（或 TRAE 项目规则文件）。
> AI 工具每次会话自动读取，无需人工提醒。

---

## 一条真源原则

文档是真源，代码是实现。

代码和文档不一致时：**先改文档，再改代码**。
禁止代码跑在文档前面。

---

## 迭代五步法（每次迭代必须按此顺序）

### 第 1 步 变更确认

新需求一句话写清楚：**改什么、不动什么、完成标准**。

```
本次变更：______________________
不改动：______________________
完成标准：______________________
```

### 第 2 步 先改文档

更新受影响的文档（在 `docs/` 下）。

> 本项目特别要求：
> - **组件/接口变更** → 同步 `21-新方向技术规格书.md`
> - **合规相关变更** → 同步 `12-工程约束清单.md` §一
> - **新增自行补充实现** → 先登记 `26-特性缺口登记表.md`，再动手（`12` T12）

### 第 3 步 再改代码

按更新后的文档实施。

### 第 4 步 验证验收

跑测试，按 `11-测试与验收标准.md` 逐条过。

### 第 5 步 写变更记录

改了什么、为什么改、哪些文档已同步。

---

## 三层防乱硬约束（违反即不合格）

### 1. 测试层（发现改坏）

每次迭代必须跑测试，**测试不过不算完成，禁止跳过**。

> 本项目：跑 `11-测试与验收标准.md` §9 的回归清单。

### 2. Git 层（改坏能退）

动手改代码前，**先 commit 当前可用版本**；
改坏了立即回滚，**不带着坏代码继续改**。

```bash
git add -A && git commit -m "checkpoint: 改动前的可用状态"
# ... 改动 ...
# 若改坏：
git reset --hard HEAD
```

### 3. 在场层（协议自动生效）

本文件位于项目根目录规则文件，**每次会话 AI 自动读取**，无需人工提醒。
