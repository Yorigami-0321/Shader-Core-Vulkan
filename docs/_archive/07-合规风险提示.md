# 文档 7：合规风险提示（含许可证分析）

> **本文档是本项目优先级最高的文档。** 任何技术决策都不能绕过它。

## 一、结论

**「假 Sodium」方案有明确的法律风险。** 在取得 Sodium 作者书面授权之前，不应采用该方案。

## 三、PolyForm Shield 1.0.0 关键条款（原文摘录）

### 3.1 Noncompete（禁止竞争）—— 命门

> **Any purpose is a permitted purpose, except for providing any product that competes with the software or any product the licensor or any of its affiliates provides using the software.**

翻译：任何用途都是允许的用途，**除了提供与「本软件」或权利人基于本软件提供的任何产品相竞争的产品**。

### 3.2 Competition（竞争的定义）—— 比想象中宽

> Goods and services compete even when they provide functionality through different kinds of interfaces or for different technical platforms. Applications can compete with services, libraries with plugins, frameworks with development tools, and so on, even if they're written in different programming languages or for different computer architectures. **Goods and services compete even when provided free of charge.** **If you market a product as a practical substitute for the software or another product, it definitely competes.**

翻译要点：
1. **换接口、换平台、换语言、换架构，都不豁免竞争认定。**
2. **免费也构成竞争。**
3. **「营销为实用替代品」= 一定构成竞争**（这是决定性证据条款）。

### 3.3 Changes and New Works —— 有限的改权

> The licensor grants you an additional copyright license to **make changes and new works based on the software for any permitted purpose.**

注意限定词：**for any permitted purpose** —— 而 permitted purpose 已被 Noncompete 排除掉「竞争」用途。所以**改 Sodium 源码同样受 Noncompete 限制**。

### 3.4 Violations —— 32 天补救窗口

> The first time you are notified in writing that you have violated any of these terms…, your licenses can nonetheless continue if you come into full compliance with these terms, and take practical steps to correct past violations, within **32 days** of receiving notice. Otherwise, all your licenses end immediately.

翻译：收到书面通知后 32 天内完全合规可补救，否则许可立即终止。

### 3.5 Distribution —— 分发义务

> You must ensure that anyone who gets a copy of any part of the software from you also gets a copy of these terms or the URL for them above, as well as copies of any plain-text lines beginning with `Required Notice:`…

翻译：分发任何含 Sodium 的部分，必须附许可全文或 URL，并保留 `Required Notice`。

## 四、本项目逐条风险对照

| 行为 | 命中哪个条款 | 风险 | 说明 |
|---|---|---|---|
| `modId="sodium"` 冒充，让 Vitrail 认它为前置 | Noncompete + Competition | 🔴 **高** | 功能上**顶替** Sodium 的位置；是「practical substitute」的典型形态 |
| 复刻包名 `net.caffeinemc.mods.sodium.*` | Competition | 🔴 **高** | 制造「同一产品」的观感；属于对 Sodium 的实质借用 |
| 复刻 37 个 `client/` 内部类的方法名与签名 | Changes and New Works（衍生争议） | 🟡 **中** | 签名偏事实信息，但**批量复刻内部结构**可能被认定衍生作品 |
| 复刻 21 个 `api/` 公开类型 | 不构成风险 | 🟢 **低** | PolyForm 明确欢迎使用；官方发布 `sodium-neoforge-api` 制品就是给这个用的 |
| 在 README/宣传里写「Sodium 的替代品」 | Competition（决定性证据） | 🔴 **高** | 该条款专门点名「marketed as a practical substitute」 |
| 不复制任何 Sodium 代码，只做自己的实现 | — | 🟢 **低** | 但前提是不复刻 FQN、不冒充 modId |
| 用官方 `api` 包 + entrypoint 集成 | 不构成风险 | 🟢 **低** | 官方 wiki 明确欢迎 |

## 五、三个方案的风险评级

| 方案 | 合规风险 | 技术可行 | 满足「零改动」 | 需要授权 |
|---|---|---|---|---|
| **A. 假 Sodium 全兼容** | 🔴 高 | 🟢 高 | ✅ | ❌ 很可能需要 |
| **B. 官方 API 插件** | 🟢 低 | 🔴 不可能 | ✅ | ✅ 不需要 |
| **C. Vitrail 独立后端**（推荐） | 🟢 低 | 🟡 中 | ❌ 需改 Vitrail | ✅ 不需要 |

### 方案 B 为什么技术上走不通

Vitrail 的 **10 个 mixin 注入目标，100% 落在 `client/` 内部**：

| 注入目标 | 在哪个包 |
|---|---|
| `DefaultChunkRenderer.rotate/prepare/render` | `client.render.chunk`（内部） |
| `ShaderChunkRenderer.begin/compileProgram` | `client.render.chunk`（内部） |
| `BlockRenderer.bufferQuad` | `client.render.chunk.compile.pipeline`（内部） |
| `DefaultFluidRenderer.render/writeQuad` | `client.render.chunk.compile.pipeline`（内部） |
| `RenderRegion.getCachedBatch/...` | `client.render.chunk.region`（内部） |
| `VKDrawContext.setContext` | `client.gpu.device.context`（内部） |
| `ChunkMeshFormats.getCurrent` | `client.render.chunk.vertex.format`（内部） |
| `SodiumWorldRenderer.initRenderer` | `client.render`（内部） |
| `ChunkVertexEncoder$Vertex.copyVertexTo` | `client.render.chunk.vertex.format`（内部） |
| `RenderSectionManager.{frame,cameraChanged,...}` | `client.render.chunk`（内部） |

而 Sodium 公开的 `api/` 包只有：`blockentity`、`config`、`internal`、`math`、`memory`、`texture`、`util`、`vertex`。

→ **Vitrail 需要的内部，公开 API 一个都不提供。**

> 这就是本项目真正的两难：**Vitrail 需要 Sodium 的内部；而 Sodium 的内部既不在公开 API 里，也不在许可允许的范围内。**

## 六、合规底线（无论选哪个方案都必须遵守）

1. **不复制 Sodium 的任何源代码**。
   即便 PolyForm 的 Changes 条款允许衍生，Noncompete 也禁止用它造竞争品。

2. **不把「Sodium 替代品」写进任何对外文字**。
   包括 README、mod 描述、Discord 发言、视频标题。Competition 条款把营销定性列为决定性证据。

3. **只参考「事实性接口信息」**。
   方法名、签名、参数顺序可以看；方法体、注释、注释风格、算法实现不能搬。
   **更稳妥的做法**：只读 Vitrail 的调用方（Vitrail 是 LGPL-3.0，且它是「客户」），**完全不看 Sodium 源码**。

4. **若要走方案 A 或 B，必须先取得 CaffeineMC 的书面授权**。
   Discord / GitHub issue 留痕均可。官方 Discord：`https://caffeinemc.net/discord`。

5. **保留 `Required Notice`**。
   分发的任何含 Sodium 制品必须附 PolyForm Shield 全文或其 URL。

6. **不要向 Sodium 提 PR**。
   其 `CONTRIBUTING.md` 明确写着：
   > "Without exception, it is required that all code being submitted to the project is of your original work. We will not accept pull requests which contain *any amount* of AI-generated code, regardless of the particular circumstances."

   本项目大量使用 AI 辅助，**向 Sodium 提 PR 会违反其贡献政策**。

7. **注意「Sodium Options API」的前车之鉴**。
   Sodium 在 Modrinth 上公开声明：
   > "Not compatible with any version of 'Sodium Options API', which is not affiliated with us, and any mods that depend on it."

   **第三方擅自做的 Sodium 兼容层被官方公开切割是有先例的。** 这既是法律风险，也是声誉风险。

## 七、推荐的合规路径（路线 C 展开）

### 第 1 步：向 Vitrail 上游提案

在 Vitrail 仓库开 issue，内容建议：

> **提案：把区块渲染后端抽象为接口，让 Vitrail 不绑定 Sodium**
>
> Vitrail 目前通过 10 个 mixin 直接注入 Sodium 内部（`DefaultChunkRenderer`、`ShaderChunkRenderer`、`RenderRegion`、`VKDrawContext` 等）。
>
> 问题：Sodium 的 PolyForm Shield 许可禁止「提供与 Sodium 竞争的产品」，第三方难以合法地提供一个 Sodium 的替代实现。
>
> 建议：把 `dev.vitrail.sodium.*` 与 `dev.vitrail.mixin.sodium.*` 抽成一个后端接口（如 `dev.vitrail.backend.ChunkRenderBackend`），Sodium 只是其中一个实现。这样：
> - Vitrail 可以支持多个后端（Sodium / 其他）；
> - 第三方后端不必复刻 Sodium 的 FQN，合规；
> - Vitrail 自身仍是 LGPL-3.0，不受影响。

### 第 2 步：一旦上游接受，实现独立后端

- 自己的 modId：`shadercore-vulkan`
- 自己的包名：`dev.shadercore.vulkan.*`
- 实现上游定义的 `ChunkRenderBackend` 接口
- 全部 GPU 操作走 `com.mojang.renderpearl.*`

### 第 3 步：不宣传为「Sodium 替代品」

定位话术：
- ✅「Vitrail 的 Vulkan 渲染后端」
- ✅「让 OptiFine 格式的着色器包在 Minecraft 自带 Vulkan 渲染器上运行」
- ❌「Sodium 的替代品」
- ❌「不需要 Sodium 也能跑」

## 八、如果坚持要走方案 A（假 Sodium）

必须完成以下前置条件，否则不建议开工：

1. ✅ 取得 CaffeineMC / JellySquid 的**书面授权**（邮件 / Discord 截图 / GitHub issue 回复）。
2. ✅ 在法律意见明确前，不公开发布、不宣传。
3. ✅ 保留完整的分发合规材料（PolyForm 全文 + Required Notice）。
4. ✅ 准备「32 天内下架整改」的预案。

**如果拿不到授权，请走路线 C。**
