## 3. 核心接口定义（本项目自己的，路线 C）

### 3.1 后端接口（由 Vitrail 上游提供，本项目实现）

```java
package dev.vitrail.backend;

/** 区块渲染后端。Sodium 与 shadercore-vulkan 各实现一个。 */
public interface ChunkRenderBackend {
    /** 后端名，用于日志与调试。 */
    String name();

    /** 是否支持本后端（通常是 Vulkan 判定）。 */
    boolean available();

    /** 世界渲染器初始化。 */
    void initRenderer();

    /** 一帧的区块渲染。 */
    void renderChunks(ChunkRenderContext ctx);

    /** 区块网格格式（供 pack 的 terrain program 读取）。 */
    ChunkMeshProfile meshProfile();

    /** 释放资源。 */
    void dispose();
}
```

> **如果上游不接受后端接口**，则退回「本项目复刻 Sodium 公开形状」的方案——但那触碰 PolyForm 风险，见文档 7。

### 3.2 本项目自己的核心类型

```java
package dev.shadercore.vulkan;

public final class VulkanChunkEngine {            // 引擎入口，单例
    public static VulkanChunkEngine instance();
    public void initRenderer();
    public void renderChunks(ChunkRenderContext ctx);
    public void dispose();
}

public final class VulkanMeshBuilder {            // 区块网格化
    // 输入：LevelSlice 等价物（区块快照）
    // 输出：顶点数组 + 索引
    public MeshResult build(ChunkSnapshot snapshot, ChunkMeshProfile profile);
}

public final class VulkanChunkRenderer {          // 实际绘制
    // 构造：GpuDevice
    public VulkanChunkRenderer(GpuDevice device);
    public void prepare(ChunkRenderMatrices matrices, RenderListSnapshot lists);
    public void draw(RenderPass pass, TerrainPassKind kind, ChunkRenderMatrices matrices,
                     GpuSampler sampler, @Nullable OitStage stage);
}

public final class VulkanSectionManager {         // 区块管理 + 剔除
    public void update(Camera camera, Viewport viewport, FogParameters fog, boolean rebuild);
    public RenderListSnapshot renderLists();
    public int totalSections();
    public int frame();
    public void frame(int value);
    public boolean cameraChanged();
    public void invalidateRenderLists();
}

public final class VulkanRenderRegion {           // 区域 + 批次
    public static final int REGION_SIZE = 16;     // ⚠️ 待与真 Sodium 核对
    public MultiDrawBatch cachedBatch(TerrainPassKind kind);
    public void clearAllCachedBatches();
    public void clearCachedBatchFor(TerrainPassKind kind);
    public void delete();
}

public final class VulkanMeshProfile {            // 顶点格式定义
    public VertexFormat vertexFormat();
    public VertexEncoder encoder();
    public static final float TEXTURE_SCALE = 32768.0f;
}
```

### 3.3 顶点扩展（承载 pack 需要的 block id）

pack 的 terrain program 需要知道每个顶点来自哪个方块。这个信息必须**骑在顶点上**（不能在 material 位里，因为半透明路径会经过排序器，material 会被覆盖）。

```java
/** 本项目的顶点扩展接口。 */
public interface ShadercoreVertex {
    int blockId();
    void blockId(int id);
    int blockOrigin();      // 打包的 (x,y,z,lightEmission)
    void blockOrigin(int packed);
}
```

顶点布局（扩展后）：

| 元素 | 类型 | 偏移 | 说明 |
|---|---|---|---|
| position | 3 × float | 0 | 方块内相对坐标 |
| color | int (ABGR) | 12 | |
| u, v | 2 × float | 16 | 纹理坐标 |
| ao | float | 24 | 环境光遮蔽 |
| light | 2 × short (打包) | 28 | 光图坐标 |
| **blockId** | **int（打包）** | **32** | `((id + 1) << 1) \| isFluid` |
| **blockOrigin** | **int（打包）** | **36** | x/y/z 各 8 bit + lightEmission 8 bit |

> 打包公式与 Vitrail 的 `SodiumVertex`/`TerrainVertex` 一致（Vitrail 的 NOTICE 说明它按 Iris 的方式打包，`((id + 1) << 1) | isFluid`）。

## 4. 状态机定义

### 4.1 引擎生命周期

```
枚举 EngineState {
    UNINITIALIZED,   // 未初始化
    INITIALIZING,    // 初始化中
    READY,           // 就绪，可渲染
    RELOADING,       // 资源重载中
    DISPOSED         // 已释放
}
```

| 迁移 | 触发 | 条件 | 禁止 |
|---|---|---|---|
| UNINITIALIZED → INITIALIZING | `initRenderer()` | GpuDevice 可用 | 重复调用 |
| INITIALIZING → READY | 设备就绪 + 着色器编译完成 | | |
| INITIALIZING → UNINITIALIZED | 初始化失败 | | 静默失败必须打日志 |
| READY → RELOADING | 资源重载 | | |
| RELOADING → READY | 重载完成 | | |
| READY/RELOADING → DISPOSED | `dispose()` | | 释放后不得再渲染 |

### 4.2 每帧渲染顺序（不可换序）

```
1. beginFrame()
2. sectionManager.update(camera, viewport, fog, rebuild)
3. sectionManager.renderLists()          → 得到要画的 section
4. renderer.prepare(matrices, lists)     → 填充批次（indirect draw 命令）
5. for each terrainPass in [SOLID, CUTOUT, TRANSLUCENT]:
     a. renderer.draw(pass, kind, matrices, sampler, stage)
6. endFrame()
```

**关键约束**：`prepare` 必须在 `draw` 之前、且**在所有 terrain pass 之前**完成（Vitrail 的注释明确写了这一点）。

### 4.3 后端选择状态机

```
枚举 BackendKind { OPENGL, VULKAN, UNKNOWN }

判定：
  if (RenderSystem.getDevice() instanceof VulkanDevice)  → VULKAN
  else if (device 非 null)                                → OPENGL
  else                                                    → UNKNOWN

规则：只要不是 OPENGL，就允许走 pack 渲染路径。
      （Vitrail 的逻辑是 `if (BACKEND == OPENGL) return;`）
```

## 8. 构建产物规格

```
产出：shadercore-vulkan-<version>+mc26.3-<loader>.jar

必须包含：
  META-INF/neoforge.mods.toml
  META-INF/MANIFEST.MF
  shadercore-vulkan.mixins.json
  dev/shadercore/vulkan/**/*.class          ← 必须有 class！

必须不包含：
  net/caffeinemc/**             ← 路线 C 下不得出现
  dev/vitrail/**                ← 不得打包 Vitrail
  net/minecraft/**              ← 不得打包游戏
```

### 8.1 构建校验脚本（进 CI）

```bash
#!/usr/bin/env bash
set -euo pipefail
JAR=$(ls build/libs/shadercore-vulkan-*.jar | head -1)

# 1. 必须有 class
if ! unzip -l "$JAR" | grep -q '\.class'; then
  echo "FAIL: jar 里没有 class 文件"; exit 1
fi

# 2. 不得含 Sodium（路线 C）
if unzip -l "$JAR" | grep -q 'net/caffeinemc/'; then
  echo "FAIL: jar 里混入了 net.caffeinemc（路线 C 不允许）"; exit 1
fi

# 3. 不得含游戏类
if unzip -l "$JAR" | grep -q 'net/minecraft/'; then
  echo "FAIL: jar 里混入了游戏类"; exit 1
fi

# 4. mixins.json 必须是 JAVA_25
if ! unzip -p "$JAR" shadercore-vulkan.mixins.json | grep -q 'JAVA_25'; then
  echo "FAIL: compatibilityLevel 不是 JAVA_25"; exit 1
fi

echo "OK: $JAR"
```

## 9. 路线 A/B 的差异（若选该路线）

若用户坚持路线 A/B，以下替换：

| 项 | 路线 C | 路线 A/B |
|---|---|---|
| modId | `shadercore-vulkan` | `sodium` |
| 包名 | `dev.shadercore.vulkan.*` | `net.caffeinemc.mods.sodium.*` + `dev.shadercore.vulkan.*` |
| 后端接口 | 由 Vitrail 提供 | 不需要（直接复刻 Sodium 形状） |
| 编译依赖 | `sodium-neoforge-api` | `sodium-neoforge`（全量） |
| 必须复刻的类 | 0 | **58 个类型 + 10 个 mixin 目标** |
| 合规风险 | 🟢 低 | 🔴 高（见文档 7） |
| 前置条件 | Vitrail 上游接受提案 | CaffeineMC 书面授权 |

**路线 A/B 必须命中的完整清单**见主计划文档 `Shader-Core-Vulkan-开发计划.md` 第 3.2 / 3.3 节。
