## 一、开工前必须做的决策（不能跳过）

**先回答这个问题：走哪条路线？**

| 路线 | 说明 | 需要你先做什么 |
|---|---|---|
| **A. 假 Sodium** | 冒充 `modId="sodium"`，完全兼容 Vitrail | ⚠️ **先联系 CaffeineMC 拿书面授权**（Discord: https://caffeinemc.net/discord），否则不要开工 |
| **B. 官方 API 插件** | 用 Sodium 公开 api 包 | ❌ 技术上走不通（Vitrail 需要 10 个内部注入点），不要选 |
| **C. 独立后端**（推荐） | 自己的 modId，Vitrail 上游配合抽后端接口 | ❌ **需要先联系 Vitrail 作者开 issue 提案**，等上游回应 |

**路线 C 的提案话术**（可直接复制到 Vitrail 仓库 issue）：

> **提案：把区块渲染后端抽象为接口，让 Vitrail 不绑定 Sodium**
>
> Vitrail 目前通过 10 个 mixin 直接注入 Sodium 内部（`DefaultChunkRenderer`、`ShaderChunkRenderer`、`RenderRegion`、`VKDrawContext`、`ChunkMeshFormats`、`ChunkVertexEncoder$Vertex`、`BlockRenderer`、`DefaultFluidRenderer`、`SodiumWorldRenderer`、`RenderSectionManager`）。
>
> 问题：Sodium 采用 PolyForm Shield 1.0.0，其 Noncompete 条款禁止「提供与 Sodium 竞争的产品」，第三方难以合法地提供一个 Sodium 的替代实现。
>
> 建议：把 `dev.vitrail.sodium.*` 与 `dev.vitrail.mixin.sodium.*` 抽成一个后端接口（如 `dev.vitrail.backend.ChunkRenderBackend`），Sodium 只是其中一个实现。这样 Vitrail 可以支持多个后端，第三方后端不必复刻 Sodium 的 FQN，也就不触碰许可证问题。
>
> 我可以提供实现（Vulkan 后端），并已把所需的契约整理成文档。

## 三、开发 AI 开工顺序（要求它遵守）

```
Phase 0  清理与骨架
         - 删掉全部虚构代码（VulkanCoreApi / VulkanDeviceMixin /
           VulkanRenderPipelineAccessor / VulkanRenderTarget）
         - 删掉 BUGS_AND_FIXES.md、verify.sh（误导性）
         - 修 settings.gradle（单工程化）
         - 修 mixins.json → JAVA_25
         - 修 mods.toml → [[dependencies.<你的 modId>]]
         验收：gradle jar 通过，jar 里含 class

Phase 1  （路线 A/B）形态兼容层
         - 按主计划 3.2 写全 58 个类型的壳
         - 方法体留空/抛异常，只保证签名正确
         验收：启动到主菜单不崩
         （路线 C 跳过此阶段）

Phase 2  可启动
         - @Mod 入口（非空）
         - 后端判定（BACKEND 必须非 OPENGL）
         - 设备/配置初始化
         验收：进世界不崩，日志显示 Vulkan 后端

Phase 3  最小可见
         - 区块网格化（最大一块工作）
         - 区块管理与剔除
         - 实际绘制委托 renderpearl
         - 区域与批次
         - 视口与视锥剔除
         验收：不加载 pack 时世界正常渲染

Phase 4  完整
         - 阴影（双矩阵、阴影贴图）
         - 半透明排序
         - OIT 分支
         - 配置 API
         - 顶点序列化
         验收：加载 BSL/Complementary 能正确着色
```

**每阶段完成标准**见文档 11。

## 四、给开发 AI 的额外要求（务必一起喂）

1. **遇到「待确认项」（文档 8 第 10 节的 12 项）时，先停下来问，不要猜。**
2. **每完成一个 Phase，跑一遍文档 11 的验收清单，并提供证据（命令输出/截图）。**
3. **不要改 Vitrail 的任何文件**（路线 C 除外，且必须等上游确认）。
4. **不要复制 Sodium 的任何代码**，包括方法体、注释。
5. **所有 GPU 操作走 `com.mojang.renderpearl.*`。**
6. **改代码前先改文档**（见文档 18 迭代维护协议）。

## 五、小白操作步骤（你只需要做这三件事）

### 第 1 件：把文档喂给开发 AI

按第二节的顺序。最简单的方式：把整个 `Shader-Core-Vulkan-docs/` 目录 + `Shader-Core-Vulkan-开发计划.md` 一起丢给它，然后说：

> 「先读 07-合规风险提示.md，然后按 17-开发投喂说明.md 的顺序开工。」

### 第 2 件：它问你问题时

| 情况 | 你怎么办 |
|---|---|
| 问题在文档里有 | 回它：「这个在文档 X 里，你重读一下」 |
| 问题超出文档 | 把它的**原话**复制回来给我（或贴到对话里），我帮你补 |
| 它说「待确认项要猜」 | **不要让它猜**，让它列出来，你贴给我 |

### 第 3 件：它说做完了

你只需要自己走一遍核心流程：

```
1. 启动游戏 → 能到主菜单吗？
2. 进世界 → 不崩吗？
3. 放一个 BSL 或 Complementary 的 pack 进 shaderpacks/ → 画面变了吗？
```

**能用就行。** 技术问题（签名、mixin、管线）不需要你判断。

## 七、常见失败症状速查（你可以自己先看）

| 症状 | 大概率原因 | 让 AI 查什么 |
|---|---|---|
| 启动就崩 | 签名不符 / 少类 | 崩栈里的类名 |
| 日志有 `Mixin apply failed` | mixin 没命中 | 报错点名的那个方法 |
| 启动正常，Vitrail 什么都不画 | `BACKEND` 恒 OPENGL | 后端判定逻辑 |
| 世界画成「彩色尖刺」 | 顶点 stride 不匹配 | 文档 11 的 5.1 节断言 |
| 世界缺块 | 网格化漏面 | 网格化实现 |
| pack 不生效 | 管线没被替换 | `compileProgram` 注入点 |
| 切 pack 后错乱 | 管线缓存没重建 | memo 的 key |
