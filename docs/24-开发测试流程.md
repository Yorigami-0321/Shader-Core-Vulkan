# 24 · 开发测试流程（给 agent 设定目标用）

> 用法：把本文 §1 的模板填好，交给 agent，agent 按 §2 的循环执行。
> 只讲步骤，不讲道理。相关背景见 `01`/`21`，红线见 `12`，验收表见 `11`。

---

## 1. 派活模板（每次派活都填这个，其余什么都不用说）

```
【目标】一句话，可观测的结果。例：屏幕上出现自定义全屏 pass 画出的纯色图案。
【不做】本次明确不碰的东西。例：不碰 pack 解析，不碰 GUI。
【完成标准】可执行的判定。例：runClient 进世界后截图有图案；日志有 vkdisp: pipeline compiled=1。
【证据】要交什么。例：截图路径 + 日志片段 + git commit hash。
【边界】允许改的目录/文件。例：只允许改 dev/vkdisp/ 与 docs/26。
【红线】本次涉及的。从 12 §四 里挑相关的抄进来。
```

**要求**
- 一次只派一个目标，不要合并
- 「不做」必须写。不写就会顺手改别的（`12` X12）
- 「完成标准」必须能被机器或截图判定，不接受「应该没问题了」

---

## 2. 执行循环（agent 每轮按此顺序）

```
① 读 22-版本基线.md          → 确认版本没漂
② 读 26-特性缺口登记表.md     → 确认本次是否要新增缺口登记
③ 改文档                     → 文档先于代码（18-迭代维护协议）
④ git commit 当前可用状态     → 改坏能退
⑤ 改代码
⑥ 跑 11-测试与验收标准.md §9 回归清单
⑦ 跑本次的「完成标准」
⑧ 失败 → 定位（§3）→ 修 → 重跑 ⑥⑦，不超过 3 轮
⑨ 通过 → 交证据（§5）→ 写变更记录 → commit
```

**任意一步没做完，不许进入下一步。**

---

## 3. 失败定位顺序（严格按序，不许跳）

```
1. 先看日志有没有 ERROR / WARN / validation error
2. 再看自己埋的诊断日志在不在（§4）
     不在 → 注入点/注册点没生效 → 查 mixin 是否被加载
3. 计数对不上？（注册数 vs 编译成功数）
     对不上 → 逐个查编译失败的 program，看编译错误原文
4. 编译通过但画面没变
     → mixin 生效了吗？目标方法签名对吗？访问到的对象是同一个实例吗？
5. 画面变了但不对（错位/尖刺/全黑/全白）
     → 查顶点 stride、纹理格式、坐标系、深度范围
6. 只在特定场景错
     → 查资源重载路径、状态恢复、pass 顺序
```

**禁止**：在没有定位到原因前就"换个写法试试"。改两处只会让你不知道是哪处生效。

---

## 4. 埋点要求（每次改动都必须满足）

| 埋点 | 位置 | 必须输出 |
|---|---|---|
| 注入点 | 每个 mixin 注入方法体第一行 | `vkdisp: [注入点名] hit` |
| 注册点 | 管线/资源注册处 | 注册计数 |
| 编译点 | 编译成功/失败 | 成功计数 + 失败时的错误原文 |
| 降级点 | 任何 fallback 分支 | `WARN` + 原因 |
| 自行补充 | `platform/` 内的补充路径 | `vkdisp: [GAP-xxx] using self-supplemented path` |

**判定标准：把日志从头读到尾，能不看画面就说出"哪些环节走到了、哪些没走到"。**
做不到 → 埋点不合格，补完了再说。

---

## 5. 交付证据（缺一不可）

```
[ ] git commit hash
[ ] 构建输出：gradlew build 的退出码与 jar 内 class 数
[ ] 相关日志片段（含 §4 的埋点输出）
[ ] 视觉证据：截图路径（或"无视觉变化"的说明）
[ ] 回归清单逐条勾选结果（11 §9）
[ ] 本次改动的文件清单
[ ] 未解决/存疑的问题（没有就写"无"）
```

**不许**用"已完成""应该好了""看起来正常"作为交付。

---

## 6. 每轮结束必须回答的三个问题

1. **本次目标达成没有？** 达成就写达成的判定依据；没达成写卡在哪一步（§3 的第几条）。
2. **有没有静默失败的可能？** 即：如果这段代码根本没生效，我能不能从日志里看出来？
3. **有没有越界？** 是否碰了「不做」清单、是否新增了未登记的自行补充（`12` T12）。

---

## 7. 硬规矩（agent 必须遵守）

```
禁止在没跑测试的情况下说"完成"
禁止在没有埋点的情况下交付
禁止一次改多个不相关的点
禁止静默降级（12 X11）
禁止在业务包直接 import com.mojang.renderpearl.*（12 T5）
禁止新增未登记的自行补充实现（12 T12）
禁止顺手改用户没点名的地方（12 X12）
禁止把「待确认项」用猜的值填（12 X9）

遇到以下情况必须停下问，不许自行决定：
- 需要引入新的第三方依赖
- 需要改 bridge/ 之外的版本相关硬编码
- 发现 OF 语义与原版能力冲突且需要自行补充
- 目标涉及对外可见的命名 / 许可证
```

## 8. 阶段目标卡（直接复制用作「目标」字段）

| 阶段 | 目标 | 完成标准 |
|---|---|---|
| **P0.1** | 空模组能构建能跑 | `gradlew build` 退出码 0；`runClient` 进主菜单；日志无 `Mixin apply failed` |
| **P0.2** | 确认跑在 Vulkan 后端 | 日志打印 `backend=VULKAN` 与设备名 |
| **P0.3** | **首个可见产物** | 屏幕上出现自定义全屏 pass 画出的图案（非黑屏、非崩） |
| **P1.1** | uniform 传递 | 改数值画面实时变化 |
| **P1.2** | 管线计数对齐 | 注册数 == 编译成功数，日志可见 |
| **P2.1** | 扫描 pack | `shaderpacks/` 下的 `.zip` 与目录都能被列出 |
| **P2.2** | 解析 shaders.properties | 选项被枚举出来，日志可见 |
| **P2.3** | `#include` | 含 `#include` 的 program 编译通过 |
| **P2.4** | composite 生效 | 开关能改变画面 |
| **P3.1** | shadow pass | 光空间列表非空，阴影贴图非全黑/全白 |
| **P3.2** | gbuffers 接管 | 地形走自定义目标 |
| **P3.3** | deferred 链 | 各步输入输出正确 |
| **P4.1** | 主流包 | BSL 主要效果可用（与 Iris 对比截图） |
| **P4.2** | 切包回归 | 切包/切 none 无残留（`11` §6 四张截图法） |
| **P4.3** | 选项 GUI | pack 声明的选项可渲染可改 |
